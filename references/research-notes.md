## lansenai：暴雨地铁检修站近身格斗

用户提供来源：
https://x.com/lansenai/status/2097165176013255100

当前环境无法直接读取 X 页面，但可通过公开镜像/案例库核对到提示词主体。可抽象出的通用方法：

- 先锁角色身份、服装、体型、配饰与阵营，不允许交换身份；
- 空间结构不是一句“某场景”，而是提前固定柱子、楼梯、栏杆、车辆等锚点；
- 摄影可以大量使用身体遮挡、柱子擦镜、甩镜、冲击抖动等隐藏切，但切后必须继承位置、朝向、动量和伤势；
- 每次关键攻击描述起点、路径、接触点和结果；
- 格挡应改变攻击方向，受击反馈匹配力量方向；
- 对手不是木桩，主角也不应无风险碾压；
- 高速动作依然要求关键接触可读；
- 结尾环境互动最好在前面已经建立，而不是突然生成道具。

这些规则可以用于现代格斗，也可以抽象迁移到武侠、奇幻和Boss战，但不能继承该案例的雨夜地铁、人物或具体招式。

## Strength04_X：结构化长提示词写法

用户提供来源：
https://x.com/Strength04_X/status/2096811204706795767

当前环境无法稳定读取该条 X 原帖的完整正文，因此**不把未核实的具体打斗内容写成事实**。通过公开镜像中该作者的多条 Seedance 提示词，可确认一种稳定的结构化方法：

- 先声明 Format/Duration/Genre/Visual Target；
- 单独建立 Character Identity Lock / Reference Lock；
- 把 Camera Direction、Visual Style、Motion Language 与 Storyboard/Timed Beats 分层；
- 时间段承担明确叙事/动作功能；
- 把禁止项放入对应模块，而不是散落在所有段落。

v3 借鉴的是这种“规格层 → 素材锁定 → 全局运动/摄影规则 → 时间轴 → 约束”的组织方式，而不是复制任何具体人物、场景或特效。

如果未来能获得该原帖截图/完整文本，可再补充精确的案例级规则；在此之前不虚构其内容。

## 其他公开社区共性

大量 Seedance 社区案例表现出相同的实用写法：

- Reference roles → format/duration → timed beats → camera/audio → must-keep constraints；
- 长片段按时间段组织，每段写主要事件与退出状态；
- 快速动作通过锁位置、朝向、动量解决切镜后瞬移；
- 每份参考素材明确工作职责，减少风格/身份/场景污染。

这些都是创作经验，不是官方成功率保证或硬参数。
